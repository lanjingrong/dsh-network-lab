# dsh-network-lab 详细使用说明

本文按“第一次安装 → 连上 eNSP → 做实验 → 排障 → 出题复习”的顺序写。命令和参数都可以直接复制到 DSH 对话框里，让 Agent 执行。

> 插件已经在当前 DSH 中加载：本会话直接出现了 `netlab_devices`、`netlab_exec`、`netlab_lab`、`netlab_verify`、`netlab_quiz`、`netlab_reference` 六个工具。
> 如果新会话看不到这些工具，先看文末“安装与卸载”。

## 先分清：每条命令在哪里输入

本插件的命令分三种，**不要混着敲**：

| 命令形式 | 在哪里输入 | 谁执行 | 例子 |
| --- | --- | --- | --- |
| `netlab_devices action=scan` 这类工具语法 | **DSH 对话框**，用自然语言或直接贴工具语法，让 Agent 调用工具 | DSH 插件（电脑上的进程） | `netlab_devices action=add id=sw1 port=2000` |
| `display version`、`system-view`、`vlan batch 10` 这类 VRP 命令 | **不要直接敲进 DSH**。要么作为 `netlab_exec` 的 `commands` 参数交给 Agent，要么在 **eNSP 设备控制台**里手动敲 | 华为设备（eNSP 里的交换机/路由器） | `netlab_exec device=sw1 commands=["display version"]` |
| `cd ...`、`powershell.exe -File install.ps1`、`npm test` | **电脑的 PowerShell 窗口**（Windows 开始菜单搜索 PowerShell） | 你的 Windows 电脑 | `cd "...\dsh-network-lab"; npm.cmd test` |

一句话记忆：

- **想操作设备** → 在 DSH 对话框里说，让 Agent 调 `netlab_exec`。
- **想验证/排障** → 同样在 DSH 对话框里说，Agent 会先调 `netlab_devices` 再调 `netlab_exec`。
- **想装插件/跑测试** → 打开 Windows PowerShell 输入。

下面每个示例都会标出“在这里输入”的位置。

---

## 1. 它到底解决什么问题

普通的大模型可以“背”出华为配置，但它看不到你的 eNSP 设备，也无法验证你是否真的配通。这个插件补上了三件事：

1. **真实连接**：通过 Telnet 连到 eNSP 设备的控制台端口，执行真实 VRP 命令。
2. **实验闭环**：任务书 → 提示 → 你配置 → 自动验证 → 复盘。
3. **学习材料**：10 个实验、12 个故障案例、18 道选择题、命名规范、变更检查卡、常用命令速查。

它不会自动创建 eNSP 拓扑，也不会替你启动 eNSP；拓扑仍然在 eNSP 里手动拖拽，插件负责“连进去操作”。

## 2. 第一次使用前的检查

### 2.1 确认插件已加载

新建一个 DSH 会话，在 **DSH 对话框**输入：

```text
列出我保存的 eNSP 设备
```

Agent 应该调用 `netlab_devices action=list`。如果返回“还没有设备”，说明插件正常，只是还没添加设备。

也可以看系统提示是否已变成“网络工程实验教练”；本插件的教学提示会自动注入。

### 2.2 确认 eNSP 已启动（在 eNSP 界面操作，不需要输入命令）

1. 打开 eNSP。
2. 拖出交换机/路由器，启动设备。
3. 等设备启动完成，双击设备应能打开命令行窗口，看到 `<Huawei>` 或 `[Huawei]`。
4. 如果设备命令行都打不开，插件一定连不上，先解决 eNSP 本身。

### 2.3 找到设备的 Telnet 端口

在 eNSP 中：

1. 右键设备 → **设置**。
2. 查看“串口”或“端口号”一栏。
3. 第一台设备通常是 `2000`，后面依次是 `2001`、`2002`……
4. “服务器地址”通常是 `127.0.0.1`。

插件默认扫描 `127.0.0.1:2000-2020`，覆盖大多数实验场景。

### 2.4 关闭占用同一端口的客户端

eNSP 的一个串口同时只能被一个客户端连接。以下程序会抢占端口：

- SecureCRT
- PuTTY
- Xshell
- 另一个 DSH 会话/另一个插件实例
- 之前没有正常关闭的 Telnet 连接

如果扫描得到端口，但连接提示“连接被重置/关闭”，先关闭这些客户端再试。

### 2.5 确认是否需要登录

- 设备直接显示 `<Huawei>`：一般不需要用户名/密码。
- 设备显示 `Username:` / `Password:`：说明配置了 AAA 或 console 认证，添加设备时要带账号。
- 设备提示修改初始密码：先在 eNSP 控制台完成密码修改，插件不会替你改密码。

## 3. 连接 eNSP 的标准五步

> 本节的 `netlab_*` 命令**全部在 DSH 对话框里输入**，不是在 eNSP 控制台、也不是在 PowerShell 里输入。

### 第 1 步：扫描端口（DSH 对话框）

在 DSH 输入框里粘贴：

```text
netlab_devices action=scan
```

也可以直接用自然语言，效果一样：

```text
帮我扫描 127.0.0.1 上 2000 到 2020 的 eNSP 端口
netlab_devices action=scan rangeStart=2000 rangeEnd=2030
```

成功时 Agent 会返回类似：

```text
| 端口 | 提示符/横幅 |
| 2000 | <Huawei> |
| 2001 | <Huawei> |
```

如果返回“没有发现开放端口”，看第 9 节排障。

### 第 2 步：保存设备（DSH 对话框）

```text
netlab_devices action=add id=sw1 name=SW1 port=2000
```

带登录认证时：

```text
netlab_devices action=add id=sw1 name=SW1 port=2000 username=admin password=你的密码
```

说明：

- `id` 是插件内部使用的短名，只能包含字母、数字、`_`、`-`，最长 32 位。
- `name` 是显示名称，可以写中文。
- `host` 不写默认 `127.0.0.1`。
- `password` 不会在工具返回里显示；但会保存在本机设备文件中，见第 10 节。

### 第 3 步：验证连接（DSH 对话框）

```text
netlab_exec device=sw1 commands=["display version", "display clock"]
```

注意：`display version` 是**华为设备的命令**，但它出现在这里只是作为 `netlab_exec` 的参数值，由 Agent 转给设备执行。你**不要**把 `display version` 单独敲进 DSH 输入框；单独敲的话 Agent 只知道“你想看版本”，最终还是帮你调 `netlab_exec`。

成功时会返回设备真实输出，例如 VRP 版本、设备型号、当前时间。看到这些就说明链路通了。

也可以直接用 `host:port`，不保存设备：

```text
netlab_exec device=127.0.0.1:2000 commands=["display version"]
```

### 第 4 步：开始配置（DSH 对话框）

```text
netlab_exec device=sw1 commands=["system-view", "sysname SW1", "vlan batch 10 20"]
```

会话会保持，下一次调用还在同一个视图里。例如接着执行：

```text
netlab_exec device=sw1 commands=["interface GigabitEthernet0/0/1", "port link-type access", "port default vlan 10"]
```

如果你更习惯自然语言，也可以这样说，Agent 会自己组命令：

```text
把 sw1 改名为 SW1，创建 VLAN 10 和 20
把 sw1 的 G0/0/1 配成 access，划进 VLAN 10
```

### 第 5 步：保存（可选，DSH 对话框）

```text
netlab_exec device=sw1 commands=["return", "display current-configuration"] save=true
```

注意：

- `save` 需要在用户视图 `<HOST>` 下执行；如果当前在 `[HOST]` 或接口视图，先 `return` 或 `quit`。
- 保存前最好先 `display current-configuration` 确认。
- 插件不会自动保存，除非你显式传 `save=true`。

### 对照：同样的事在 eNSP 控制台里怎么做

如果你不想用 Agent，也可以在 eNSP 里双击设备，在弹出的控制台窗口里直接敲 VRP 命令：

```text
<Huawei> system-view
[Huawei] sysname SW1
[SW1] vlan batch 10 20
```

| 目的 | DSH 对话框 | eNSP 设备控制台 |
| --- | --- | --- |
| 扫描端口 | `netlab_devices action=scan` | 没有对应操作 |
| 看版本 | `netlab_exec device=sw1 commands=["display version"]` | `display version` |
| 改名 | `netlab_exec device=sw1 commands=["system-view","sysname SW1"]` | `s`（回车补全）→ `sysname SW1` |
| 保存 | `netlab_exec ... commands=["return","save"] save=true` | `return` → `save` → `y` |

**两者不要同时操作同一台设备**：eNSP 控制台打开时也会占用该串口，Agent 再去连会被拒绝。要么关掉 eNSP 控制台窗口，要么先 `netlab_devices action=disconnect`。

## 4. 十二个工具的参数与用法

### 4.1 `netlab_devices`：设备管理

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `action` | string | `list` / `add` / `remove` / `scan` / `adopt` / `disconnect` |
| `id` | string | 设备 id，add/remove/disconnect 时使用 |
| `name` | string | 显示名称 |
| `host` | string | 默认 `127.0.0.1` |
| `port` | integer | eNSP 控制台端口 |
| `username` | string | 登录用户名，可空 |
| `password` | string | 登录密码，可空；不会回显 |
| `notes` | string | 备注 |
| `rangeStart` / `rangeEnd` | integer | 扫描范围，默认 2000-2020，单次最多 201 个端口 |
| `newPort` | integer | adopt 时探测的端口；不填则在扫描范围内找未登记的开放端口 |
| `newId` / `newName` | string | adopt 时的设备 id / 显示名；不填用 `dev-<端口>` 和识别出的型号 |

常用命令（**都在 DSH 对话框输入**）：

```text
netlab_devices action=list
netlab_devices action=scan
netlab_devices action=adopt port=2000          ← 一键导入并识别型号（推荐）
netlab_devices action=add id=sw1 name=SW1 port=2000
netlab_devices action=remove id=sw1
netlab_devices action=disconnect id=sw1
netlab_devices action=disconnect
```

`disconnect` 不传 id 会关闭所有活动会话。

> **adopt 与 add 的区别**：eNSP 里新增第二台设备后，它的串口号往往不是 2000（要右键 → 设置 → 配置 里看）。`action=adopt port=<串口号>` 会探一次端口、按提示符自动认型号（S5700 → 交换机，USG → 防火墙，AR → 路由器），再直接写进设备表；端口已登记、设备要登录（Username:/Password:）、设备还在开机，都会给出对应提示，不会瞎写。


> `remove` 只删除插件里保存的设备记录，不会删除 eNSP 里真实存在的设备；`disconnect` 只断开会话，配置不受影响。

### 4.2 `netlab_exec`：执行命令

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `device` | string | 设备 id，或 `host:port` |
| `commands` | string[] | 按顺序执行，单次最多 25 条，每条最多 512 字符，不能带换行 |
| `timeoutMs` | integer | 每条命令等待时间，默认 15000，范围 2000-60000 |
| `save` | boolean | 执行完是否保存配置 |
| `newSession` | boolean | 先关闭旧会话再重连 |
| `allowDestructive` | boolean | 允许破坏性命令，默认 false |

示例（**在 DSH 对话框输入**，`commands` 里的每条是设备命令，由 Agent 转给设备）：

```text
netlab_exec device=sw1 commands=["display interface brief"]
```

```text
netlab_exec device=sw1 commands=["system-view", "interface GigabitEthernet0/0/1", "description to-PC1", "quit"]
```

```text
netlab_exec device=sw1 commands=["return", "save"] save=true
```

默认拒绝的命令包括：

- `reboot`
- `reset saved-configuration`
- `format`
- `delete ...`
- `undo startup ...`
- `startup saved-configuration ...`
- `factory-configuration`

如果确实需要执行（例如实验课要求恢复出厂），必须先让用户确认设备、影响和备份，再传：

```text
netlab_exec device=sw1 commands=["reset saved-configuration"] allowDestructive=true
```

### 4.3 `netlab_lab`：实验任务书

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `action` | string | `list` / `show` / `hint` / `solution` |
| `lab` | string | 实验 id |
| `hintIndex` | integer | 提示级别，从 0 开始 |

流程（**都在 DSH 对话框输入**）：

```text
netlab_lab action=list
netlab_lab action=show lab=vlan-basic
netlab_lab action=hint lab=vlan-basic hintIndex=0
netlab_lab action=hint lab=vlan-basic hintIndex=1
netlab_lab action=solution lab=vlan-basic
```

- `show`：只给任务书、拓扑、验证点，不给答案。
- `hint`：逐级提示，适合“先自己想”的学习模式。
- `solution`：完整参考配置，建议自己配完再看。

### 4.4 `netlab_verify`：自动验证

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `lab` | string | 实验 id |
| `bindings` | array | 把拓扑角色绑定到真实设备 id（与 `auto` 二选一） |
| `auto` | boolean | `true` 时按当前设备表自动配对角色，不用手写 bindings |
| `timeoutMs` | integer | 每条检查命令超时，默认 12000 |

示例（**在 DSH 对话框输入**）：

```text
netlab_verify lab=vlan-basic auto=true
```

返回三种状态：

> `auto=true` 的配对规则：角色名（`SW1`/`R1`/`AR1`）先去设备 id、再去设备名称里找包含关系（不分大小写），找不到就按设备表顺序顺延；配不上的角色标 `skip`，不会乱连。返回结果第一行会写明“自动绑定：SW1 → sw1，R1 → r1”。

- ✅ `pass`：输出匹配预期。
- ❌ `fail`：输出不匹配，或设备连不上。
- ⏭ `skip`：该角色没有绑定设备。

验证只运行 `display` 类只读命令，不会改配置。

### 4.5 `netlab_quiz`：选择题

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `action` | string | `new` / `grade` / `topics` |
| `topics` | string[] | 主题过滤，例如 `["OSPF","NAT"]` |
| `count` | integer | 1-10，默认 5 |
| `quizId` | string | 批改时使用 |
| `answers` | string[] | 按题号顺序的答案，如 `["B","C","A"]` |

示例（**在 DSH 对话框输入**；也可以直接说“出 5 道 VLAN 题”）：

```text
netlab_quiz action=topics
netlab_quiz action=new topics=["VLAN","STP"] count=5
netlab_quiz action=grade quizId=quiz-xxxx answers=["B","C","A","D","B"]
```

答案支持 `A-D` 或 `1-4`。批改后会给出每题解释和得分。

### 4.6 `netlab_reference`：命令速查

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `topic` | string | `vlan` / `static-route` / `ospf` / `nat` / `acl` / `dhcp` / `stp` / `troubleshoot` / `all` |
| `query` | string | 自由关键词，例如 `trunk`、`邻居`、`反掩码` |

示例：

```text
netlab_reference topic=ospf
netlab_reference query=trunk
```

### 4.7 `netlab_curriculum`：HCIA 学习路线

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `action` | string | `list` / `progress` / `next` / `phase` / `complete` / `reset` / `note` |
| `phase` | string | 阶段 id，例如 `phase-2`（也可以只写 `2`） |
| `force` | bool | `complete` 时跳过过关校验，默认 `false` |

示例：

```text
netlab_curriculum action=list
netlab_curriculum action=next
netlab_curriculum action=phase phase=phase-2
netlab_curriculum action=complete phase=phase-2
netlab_curriculum action=progress
```

说明：

- 共 10 个阶段（phase-0 到 phase-9），由易到难。每个实验、每个故障案例、每个题库主题都挂在某个阶段上，不会出现“学了阶段却不知道做哪个实验”。
- `progress` / `next` / `phase` 都会附带**过关条件**和**接下来做什么**：本阶段的主实验、扩展实验、故障案例、自测命令一次列全。
- **阶段完成有硬门槛**：主实验用 `netlab_verify` 验证通过过（本会话内），并且本阶段题目正确率 ≥ 80%，`action=complete` 才会计入。没通过它会告诉你还差哪一项。
- 确实已经掌握的阶段，可以 `action=complete phase=phase-1 force=true` 自己跳过校验（会标注“force 跳过校验”）。
- phase-0、phase-1 没有对应题目，做完主实验验证通过即可。
- 进度会写入 `%DSH_HOME%\network-lab\progress.json`（与 `devices.json` 同目录），重启 DSH 后自动恢复。
- 可用环境变量 `DSH_NETLAB_PROGRESS` 指定其他路径。
- `action=note` 给阶段写备注，例如 `netlab_curriculum action=note phase=phase-2 note="trunk 放行顺序还要练"`。
- `action=reset` 只清空完成标记，备注保留。

### 4.8 `netlab_fault`：故障排查案例

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `action` | string | `list` / `show` / `answer` |
| `id` | string | 案例 id；`show` 不传则随机 |
| `level` | string | `list` 时过滤：`初级` / `中级` / `高级` |
| `layer` | string | `list` 时过滤：`二层` / `三层` / `策略` / `DHCP` |
| `inject` | boolean | `answer` 时是否把故障注入设备（会改配置，需你同意） |
| `bindings` | array | 角色到设备绑定，`inject=true` 时必填 |

示例：

```text
netlab_fault action=list
netlab_fault action=list level=中级
netlab_fault action=show id=f01-vlan-mismatch
netlab_fault action=answer id=f01-vlan-mismatch
netlab_fault action=answer id=f01-vlan-mismatch inject=true bindings=[{"role":"SW1","device":"sw1"}]
```

说明：

- `show` 是**学习模式**：只给症状和分层排查步骤，不给根因。
- `answer` 才给根因、修复命令和复盘问题。
- `inject=true` 会把故障真的写进设备（例如删掉 trunk 的 VLAN 放行），注入后会报告执行了什么。

### 4.9 `netlab_skillcheck`：能力自检

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `phase` | string | 只检查某一阶段；不传则检查全部 |

示例：

```text
netlab_skillcheck
netlab_skillcheck phase=phase-4
```

每个阶段给出完成清单，你可以逐条回答“会 / 不会”，AI 再针对不会的项出题。

### 4.10 `netlab_standard`：华为命名与编号规范

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `action` | string | `index` / `sysname` / `description` / `vlan` / `review` |
| `site` | string | 站点缩写，例如 `BJ` / `SH` / `IDC` |
| `role` | string | 设备角色，例如 `CORE` / `AGG` / `ACC` / `FW` / `WAN` |
| `index` | integer | 序号，1-99 |
| `config` | string | `review` 时贴入的配置片段 |

示例：

```text
netlab_standard action=sysname site=BJ role=CORE index=1
netlab_standard action=description
netlab_standard action=vlan
netlab_standard action=review config="sysname Huawei\nvlan batch 1 1002\n..."
```

说明：

- `sysname` 按 `<站点>-<角色>-<序号>` 生成，例如 `BJ-CORE-01`。
- `review` 是启发式检查，会挑出默认 sysname、保留 VLAN、trunk 放行 all、接口无 description、关闭 STP 等问题。
- 错误级问题建议改完再上设备，警告级要人判断。

### 4.11 `netlab_checklist`：变更检查卡

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `action` | string | `list` / `show` / `lab` |
| `id` | string | `before-change` / `during-change` / `after-change` / `troubleshoot` |
| `lab` | string | 按实验生成专属检查表 |

示例：

```text
netlab_checklist action=list
netlab_checklist action=show id=before-change
netlab_checklist action=lab lab=vlan-basic
```

每张卡包含：检查项、对应命令、必做/建议标记、以及“红线”（必须讲清后果的那几条）。

### 4.12 `netlab_reboot`：安全重启验证

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `device` | string | 设备 id，或 `host:port` |
| `phase` | string | `preflight`（只检查，不重启）或 `reboot`（真正重启） |
| `confirm` | boolean | `reboot` 阶段必须为 `true` |
| `check` | string[] | 重启后自检命令，默认 `display version` 与 `sysname` |
| `waitMs` | integer | 等待设备恢复的最长时间，默认 120000，最大 300000 |

两阶段用法：

```text
netlab_reboot device=sw1 phase=preflight
# 看清单，确认“运行配置 == 已保存配置 ✅ 一致”
netlab_reboot device=sw1 phase=reboot confirm=true
```

preflight 会对比 `display current-configuration` 与 `display saved-configuration` 的 sysname：

- ✅ 一致 → 提示可以重启，并给出执行命令
- ❌ 不一致 → 建议先 `save`，不让你把没保存的配置重启丢掉

`reboot` 阶段会**再复核一次**保存状态，中间有未保存修改会直接拒绝。重启后自动轮询端口，设备恢复后跑自检，最后报告“配置是否真的落盘”。

> 不要用 `netlab_exec commands=["reboot"]` 硬重启；它会被破坏性命令保护拦下，并提示改用 `netlab_reboot`。

### 4.13 踩坑知识库与故障出题

**踩坑知识库（20 条）**

```text
netlab_reference topic=pitfall
netlab_reference topic=pitfall query=p03-view-mismatch
netlab_reference query=Wrong parameter found at "^" position.
```

`netlab_exec` 失败时，结果末尾会自动附：

```text
### 你可能踩了这些坑

**提示符不对就是视图不对**（`p03-view-mismatch`）
- 原因：在用户视图 <HOST> 敲了接口命令，或在接口视图敲了系统视图命令。
- 先查：`看当前提示符是 < > 还是 [ ]`、`display current-configuration 看上下文`
- 处理：`system-view`
```

覆盖：启动慢、端口占用、视图错、接口不存在、save 视图/确认、反掩码、trunk 放行、ACL 隐含拒绝、AAA 锁死、VLANIF DOWN、无回程路由、OSPF 定时器、分页、STP ALTE、PC 网关、debugging、VLAN 1 滥用、重启优先等。

**故障 → 出题联动**

```text

netlab_fault action=show id=f01-vlan-mismatch quiz=false  # 只要案例

```

每个故障都绑定到题库里具体题目，练完立刻测；“讲完不测”不算闭环。

### 完整走一遍 `vlan-basic`

> 本节第 1-5 步、第 7 步里的 `netlab_*` 命令都在 **DSH 对话框**输入；

```text
PC1(192.168.10.10/24) --- G0/0/1 [SW1] G0/0/24 ===== G0/0/24 [SW2] G0/0/1 --- PC3(192.168.10.30/24)
```

```text
  "quit",

  "quit"
]
```

**第 6 步：数据面测试（eNSP 里双击 PC）**

## 7. 会话、超时和重连

### 7.1 会话会保持

`netlab_exec` 第一次调用会建立 Telnet 会话，后续调用复用同一个会话。在 **DSH 对话框**里可以连续输入：

```text
netlab_exec device=sw1 commands=["system-view"]
netlab_exec device=sw1 commands=["sysname SW1"]
netlab_exec device=sw1 commands=["interface GigabitEthernet0/0/1"]
```

而不必每次重新登录。

### 7.2 空闲回收

会话空闲超过 15 分钟会被回收；下次调用自动重连。DSH 退出时会关闭所有会话。

### 7.3 卡住时重连

```text
netlab_exec device=sw1 commands=["display version"] newSession=true
```

或者：

```text
netlab_devices action=disconnect id=sw1
```

### 7.4 超时

- 默认每条命令 15 秒。
- 大配置/`display current-configuration` 可以调到 30000。
- 如果设备一直不出提示符，通常是：
  - 命令进入了交互确认（`[Y/N]`）
  - 输出分页没有处理
  - 设备 CPU 忙
  - 会话已经被其他客户端抢占

## 9. 常见问题排查

> 下表的“处理”列：带 `netlab_` 的在 **DSH 对话框**输入；带 `display`/`ping` 的在 **eNSP 设备控制台或 PC 命令行**输入。

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 扫描不到端口 | eNSP 没启动设备 / 端口不是 2000 / 防火墙 | 启动设备；右键设置确认端口；换范围扫描 |
| 端口开放但没提示符 | 设备还在启动 / 控制台需要按回车 | 等 10-30 秒；在 eNSP 控制台按回车 |
| 连接被重置 | 端口被 SecureCRT/PuTTY 占用 | 关闭其他客户端，`newSession=true` 重试 |
| `Username:` 后卡住 | 没提供用户名 | DSH：`netlab_devices action=add ... username=... password=...` |
| 登录后马上断开 | 账号权限不足 / AAA 限制 | 先在 eNSP 控制台确认能登录 |
| 命令超时 | 分页、确认交互、设备忙 | 设备上执行 `screen-length 0 temporary`；避免一次发太多；DSH 里 `newSession=true` 重连 |
| 输出有乱码 | Telnet 控制字符 / 编码 | 插件会清理大部分控制字符；仍有问题请把原始输出贴给 Agent |
| `save` 失败 | 当前在系统视图/接口视图 | DSH：`netlab_exec device=sw1 commands=["return"] save=true` |
| 验证失败但 ping 通 | 验证正则只检查配置/状态 | 看 `netlab_verify` 返回的 `detail`，必要时手动 `display` |
| 命令被拒绝 | 命中破坏性命令保护 | 向用户确认后传 `allowDestructive=true` |

### 分层排障顺序

这 7 行是**设备命令**。在 DSH 对话框里让 Agent 依次执行：

```text
netlab_exec device=sw1 commands=["display interface brief"]
netlab_exec device=sw1 commands=["display vlan", "display port vlan active"]
netlab_exec device=sw1 commands=["display arp", "display ip routing-table"]
netlab_exec device=sw1 commands=["display acl 3000", "display nat session all"]
```

数据面测试（ping/tracert）在 **eNSP 的 PC 命令行**里做；如果是路由器之间，也可以在路由器上：

```text
netlab_exec device=r1 commands=["ping -c 4 192.168.2.10"]
```

只读命令与层级对应：

```text
1. display interface brief          # 物理/接口
2. display vlan                     # 二层
3. display port vlan active         # PVID/trunk
4. display arp                      # 三层邻居
5. display ip routing-table         # 路由
6. display acl / nat session        # 策略
7. ping / tracert                   # 数据面
```

## 10. 安全、数据和限制

### 10.1 密码保存

设备信息保存在本机 JSON 文件，默认：

```text
%DSH_HOME%\network-lab\devices.json
```

如果 DSH 以 profile 目录为工作目录运行，工具也可能返回 profile 下的：

```text
%DSH_HOME%\profiles\<profile>\.dsh\network-lab\devices.json
```

以 `netlab_devices action=list` 返回的“配置文件”路径为准。

密码是明文保存的（POSIX 下会尝试 `chmod 600`），仅适合本机实验环境。不要把该文件提交到 Git，也不要用真实生产密码。

### 10.2 Telnet 是明文协议

插件连接的是 eNSP 本机 Telnet 控制台，流量不加密。不要把它暴露到公网，也不要用它管理生产设备。

### 10.3 破坏性命令

默认拒绝：

```text
reboot
reset saved-configuration
format
delete
factory-configuration
```

`allowDestructive=true` 只是关闭插件的保护，不会替你确认；使用前必须让用户明确知道设备、影响和恢复方式。

### 10.4 不自动保存

插件不会自动 `save`。需要保存时显式传 `save=true`，并在保存前让用户确认。

### 10.5 当前限制

- 只支持 Telnet，不支持 SSH。
- 不创建/启动 eNSP 拓扑。
- 不解析图形化拓扑，拓扑需要你用文字/ASCII 描述。
- 自动验证依赖内置实验的检查项；自定义实验需要自己写 `display` 命令判断。
- 不替代真实设备实验；eNSP 行为与真机可能有差异。

### 10.6 中文乱码（0.5.1 已修）

eNSP 在中文 Windows 上把控制台输出按 **GBK** 发送，而旧版本一律按 UTF-8 解码，结果设备名、接口 `description` 里的中文变成 `S5700-瀛︿範鏈?` 这种样子，而且一重启更乱。

0.5.1 起：

- 连接时按字节内容判断编码（UTF-8 还是 GB18030），之后同一条会话固定用这个编码，所有 `display` 输出、报错、提示符走同一套解码。
- 一个汉字被拆在两个 TCP 包里也能正确拼回，不会吞字。
- 编码判断要等**至少两个高位字节**到齐才下结论，所以编码定下来之前先按 ASCII 显示的那几行（比如 `sysname ` 前缀）会被整体收回、按正确编码重发一次，屏幕上不会出现缺字或半截名字；提示符不带换行也能立刻显示，登录不会卡住。
- 纯英文设备（从没出现过中文）整个会话都按 ASCII/UTF-8 处理，零开销。
- `netlab_devices` 读设备列表时会顺手修一次以前存下的乱码名（当初是按 Latin-1 存下来的那种）。
- 已经被旧版本写成替换符（`�`，U+FFFD）的名字无法还原，重新 `netlab_devices action=add` 一次正确名字即可。

仍然乱码时，先在 eNSP 控制台里敲 `display current-configuration | include description`，确认是设备端输出本身有问题，还是插件解码有问题。

### 10.7 阶段标记不了完成（0.6.0 起）

0.6.0 起 `netlab_curriculum action=complete` 先查过关条件，没过关会返回“**还没过关，先不计入完成**”，并列出差哪一项：

| 状态 | 意思 | 怎么补 |
| --- | --- | --- |
| `[ ] 做完主实验 xxx` | 本会话内没用 `netlab_verify` 验证通过过这个实验 | `netlab_verify lab=xxx auto=true` |
| `[ ] 题目正确率 ≥ 80%（尚未测）` | 本阶段题目还没测 | `netlab_quiz action=new topics=["VLAN","Trunk","STP"] count=5` |
| `[ ] 题目正确率 ≥ 80%（60%）` | 测了但没过 | 看批改里的解析，重测，直到 ≥ 80% |

两点说明：

- 实验记录只在本会话内有效；DSH 重启后要重新 `netlab_verify` 一次（它只用只读 `display` 命令，几秒钟）。
- 确实已经掌握的阶段可以 `force=true` 跳过，输出会标注“force 跳过校验”，之后仍可正常记录进度。

## 12. 更新与卸载

> 本节命令在 **Windows PowerShell** 里输入，不是在 DSH 对话框，也不是 eNSP。

### 更新

替换插件目录内容后，重启 DSH。若只改了 Host 侧 JS，部分环境支持 HMR，但 **最稳妥仍是重启**。

### 卸载

下面给出两条路：用 PowerShell 改文件，或手动改。

**方式 A：PowerShell**

```powershell
cd "C:\Users\laola\Documents\deepseek-harness\default-workspace\dsh-network-lab"
# 1. 查看安装脚本留下的备份
Get-ChildItem "$env:DSH_HOME\profiles\desktop" -Filter *.bak-* | Sort-Object LastWriteTime -Descending
# 2. 用最新备份恢复（把 <时间戳> 换成上一步看到的）
# Copy-Item "$env:DSH_HOME\profiles\desktop\package.json.bak-<时间戳>" "$env:DSH_HOME\profiles\desktop\package.json"
# Copy-Item "$env:DSH_HOME\profiles\desktop\cordis.patch.yml.bak-<时间戳>" "$env:DSH_HOME\profiles\desktop\cordis.patch.yml"
# 3. 删除 node_modules 联接
cmd /c rmdir "$env:DSH_HOME\profiles\desktop\node_modules\dsh-network-lab"
# 4. 删除 Skill（可选）
Remove-Item "$env:DSH_HOME\skills\network-lab" -Recurse -Force
# 5. 删除设备文件（可选，删除后保存的密码无法恢复）
Remove-Item "$env:DSH_HOME\network-lab" -Recurse -Force
```

然后重启 DSH。

**方式 B：手动编辑**

1. 编辑 `%DSH_HOME%\profiles\desktop\package.json`：
   - 从 `dependencies` 删除 `dsh-network-lab`
   - 从 `dsh.profile.bundles` 删除 `dsh-network-lab`
2. 编辑 `%DSH_HOME%\profiles\desktop\cordis.patch.yml`，删除 `dsh-network-lab` 的 insert 行。
3. 删除 `node_modules\dsh-network-lab` 联接。
4. 重启 DSH。
5. 如需要，删除 `%DSH_HOME%\network-lab\devices.json` 和 `%DSH_HOME%\skills\network-lab`。

安装时会自动备份 `package.json` 和 `cordis.patch.yml`，文件名带时间戳，可作为恢复点。

## 13. 最短上手清单

> 下面第 2-8 步都在 **DSH 对话框**输入。

```text
# 第 1 步：在 eNSP 界面里启动设备，右键设备→设置，确认端口 2000

# 第 2 步：DSH 对话框
netlab_devices action=scan
# 第 3 步：DSH 对话框
netlab_devices action=add id=sw1 name=SW1 port=2000
# 第 4 步：DSH 对话框
netlab_exec device=sw1 commands=["display version"]
# 第 5 步：DSH 对话框
netlab_lab action=list
# 第 6 步：DSH 对话框
netlab_lab action=show lab=vlan-basic
# 第 7 步：自己配置后，在 DSH 对话框验证
netlab_verify lab=vlan-basic auto=true
# 或手工绑定：netlab_verify lab=vlan-basic bindings=[{"role":"SW1","device":"sw1"}]
# 第 8 步：在 DSH 对话框复习
netlab_quiz action=new topics=["VLAN"] count=5
```

**输入位置速记：**

| 你要做的事 | 打开哪个窗口 |
| --- | --- |
| 建拓扑、启设备、看端口号 | eNSP 界面 |
| 让 AI 扫描/连接/配置/验证/出题 | DSH 对话框 |
| 装插件、跑测试、改 profile 文件 | Windows PowerShell |
| 手动敲 VRP 命令（不经过 AI） | eNSP 设备控制台（双击设备弹出） |

如果只记一句：**先 scan，再 add，再 display version；确认通了再配置。全程都在 DSH 对话框输入。**
